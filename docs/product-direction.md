# 归流产品方向与设计约束

状态：产品方向与实施约束；当前迭代限于阶段 A、B。日期：2026-10-21。

本文约定归流服务于谁、提供哪些能力，以及后续功能必须遵守的边界。它描述目标方向，不代表所有能力已经实现；当前事实访问行为仍以[安全数据访问契约](security-data-access.md)为准。本文不固定数据库表、具体 API 路径、接口命名或开发排期。

## 1. 产品定位

**归流是供安全人员、企业软件和 Agent 共用的安全数据访问层。统一安全数据，不统一安全结论。**

归流接入云安全产品、云资源管理接口、已有 SIEM / SOC 和审计数据源，提供一致的查询语义、明确的数据覆盖范围，以及能够返回来源记录的证据路径。

云安全告警是第一种接入的数据。资产上下文和审计事件是后续围绕调查任务扩展的数据类型。所有扩展都应减少使用者获取和理解事实的成本。

使用者应能围绕一个告警或一个资源，查询“发生了什么、这是什么资产、有哪些已知配置和观测、还有哪些相关记录”，再使用自己的规则、Agent 或人工分析得出结论。

## 2. 服务对象

| 对象 | 主要需求 | 归流提供的价值 |
| --- | --- | --- |
| 多云安全工程师与调查人员 | 查询不同产品中的告警、资产背景和证据 | 统一检索、资产上下文、来源追溯，减少控制台切换 |
| 安全自动化与 Agent 开发者 | 持续、按需取得可处理的数据 | 稳定的类型契约、增量变化、分页、覆盖信息与精确证据 |
| 企业平台与安全集成开发者 | 为内部工具提供公共数据接口 | 维护一层接入，供多个消费端复用 |
| 已有 SIEM / SOC 的团队 | 补充尚未覆盖的数据源或提供一致访问 | 按实际缺口接入，复用已经保存的数据 |

优先验证同时使用两个以上安全数据源、已有调查或自动化任务、正在承担接口维护成本的团队。企业规模和是否使用 AI 都不单独决定适用性。

Web、REST API、MCP 与只读查询 CLI 是同一套事实能力的消费入口。Agent 是重要使用者，人工与普通程序也具有同等的数据访问地位。

## 3. 核心使用任务

1. 使用者查到一条告警，取得来源身份、时间、检测规则和原始证据。
2. 系统根据告警明确引用的资源，返回该资产的基本信息、网络配置、软件与产品、标签，以及各部分的数据状态。
3. 使用者按资源身份、账号、IP、用户和时间，继续查询其他告警、资产观测或审计事件。
4. 使用者按需展开少量原始证据，形成自己的调查结论。
5. 企业程序通过增量接口持续消费本地已经记录的变化，使用自己的调度、研判和响应流程。

首屏或首次上下文请求应足以帮助使用者识别机器及其主要背景。大量规则、软件清单和事件明细继续分页读取，摘要必须提供数量、截断说明和展开路径。

## 4. 不可妥协的原则

| 原则 | 约束 |
| --- | --- |
| 忠于来源 | 厂商判断作为来源声明保留；归流不新增攻击成功、误报、风险高低或应否处置的结论 |
| 确定性转换 | 标准字段与派生值具有输入路径、转换规则和版本，能够重放、验证 |
| 无损组织 | 在明确的保留范围内保留来源记录与修订，筛选、分组和摘要均可展开到成员及证据 |
| 身份与时间准确 | 明确区分云身份与本地连接配置，区分事件时间、来源更新时间、观测时间和采集时间 |
| 能力与缺口可见 | 未知、未授权、未接入、失败、过期和查询无结果必须能够区分 |
| 消费端独立 | 稳定契约供各类客户端使用，业务调度、研判与响应由使用者决定 |

字段重命名、格式转换、精确匹配、分组计数、单位换算和明确配置的解析都属于允许的数据处理。复杂度本身不决定是否越界；输出必须能由明确输入和规则解释，并保持来源语义。

## 5. 数据范围

| 数据类型 | 应提供的内容 | 主要边界 |
| --- | --- | --- |
| 安全发现 Finding | 云安全告警、已有检测结果，以及按来源语义接入的漏洞、配置或合规发现 | 保留厂商原始类别、等级、状态和证据，不自行生成检测结果 |
| 资产及其观测 | 云资源身份、配置、网络、软件与产品、标签，以及来源明确报告的状态 | 可定位资源、来源和时间；不宣称完整 CMDB 或全网资产覆盖 |
| 审计与安全事件 | 云操作审计，以及其他系统中可按需检索的事件 | 明确数据类型、查询能力、时间与授权范围 |
| 来源与覆盖信息 | 接入配置、权限范围、同步进度、失败、延迟、保留期和查询限制 | 数据结果必须与这些限制一起解释 |

SIEM / SOC 是接入来源，其返回结果应按实际类型表达。来源中的告警与原始事件分别保留。相同内容从多个系统取得时保留来源身份；只有存在明确、可追溯的来源关系时才提供等价引用，不能默默删除其中一份。

## 6. 资产上下文是核心能力

### 6.1 什么是资产

资产是由来源明确标识、可以被引用的资源。初期重点覆盖云主机及其直接相关的网卡、网络与安全组，后续根据任务扩展容器、数据库、负载均衡等资源。

资产身份使用原生 ID 或完整资源名，并携带厂商、真实账号或项目、资源类型、适用的地域及命名空间。全局资源允许明确的全局作用域，不强行补地域。

本地连接 ID、显示名称、IP 和标签都不能单独充当跨源资产身份。身份信息不足时保留来源观测，返回未解析的资源引用或候选匹配。

资产支持独立检索，不要求先产生告警。从告警中提取的资源引用不等于完成资产发现；资产清单的覆盖范围必须单独说明。

### 6.2 应包含的字段

以下是长期目标字段范围，各连接器按实际来源能力提供。阶段 B 首版只要求控制面可可靠取得的实例身份、账号、地域、操作系统、公私网 IP、VPC、子网、安全组与标签；软件、进程、监听端口、EDR 和安全 Agent 状态按来源需求后续补充，不阻塞首版交付。未取得的字段保持未知，并说明原因。

| 类别 | 字段与内容举例 | 数据约束 |
| --- | --- | --- |
| 身份与归属 | 原生资源 ID、名称、资源类型、厂商、账号、项目、订阅、地域、可用区 | 原生身份与本地别名分别保存 |
| 机器基本信息 | 实例规格、操作系统、镜像、运行状态、来源报告的创建时间 | 不从名称或告警标题猜操作系统与用途 |
| 网络身份 | 公私网 IP、网卡、VPC、子网、关联负载均衡 | 多值保留，明确来源和观测时间 |
| 端口与服务 | 来源报告的监听地址、协议、端口、服务名、关联进程 | 与安全组配置、可达性观测分别表达 |
| 安全组与网络策略 | 绑定的安全组 ID、名称、入站/出站规则、协议、端口范围、地址或对象引用、动作及适用优先级 | 保留规则原义及对象引用，不把允许规则直接写成可达端口 |
| 软件与部署产品 | 来源报告的软件、应用、服务、版本、容器镜像和部署位置 | 名称、版本、运行状态按来源能力分别提供 |
| 安全产品覆盖 | 关联安全产品、Agent 安装状态、来源报告的在线或保护状态 | “关联产品”“已安装”“在线”“受保护”分别表达 |
| 标签与业务元数据 | 云原生标签，以及来源明确提供的负责人、环境、业务归属 | 保留来源、原键值与命名空间，不把标签推断为已验证事实 |
| 来源与时效 | 来源系统、原始记录、字段溯源、观测时间、采集时间、修订、过期状态 | 每个信息组件可以有独立来源和时间 |

### 6.3 “开放端口”必须拆开表达

| 信息 | 含义 | 可接受的依据 |
| --- | --- | --- |
| 配置允许的端口 | 某条安全组或网络策略允许相应流量 | 云控制面或其他明确策略来源 |
| 观测到的监听端口 | 某地址上有进程或服务监听 | 已有主机、安全产品或资产清单接口的观测 |
| 来源报告的可达端口 | 某来源在特定时间、特定探测起点观察到端口可达 | 已有探测结果，附带起点、目标、协议与时间 |

归流不把这三类合并为一个没有依据的 `open_ports`。安全组允许 22 端口，不代表机器正在监听，也不代表互联网可以访问。

来源明确提供的暴露或可达性结论可以作为来源声明展示。未来如果增加配置路径计算，必须另行设计输入范围与算法版本，并明确它是配置推导，不能替代实际可达性观测。

### 6.4 “部署了什么产品”的边界

软件与产品信息可来自云资源元数据、已有主机安全或 EDR、容器平台、资产清单及企业已有系统。归流维护这些接口，不要求自行安装采集 Agent、登录主机或运行扫描器。

端口号不能直接证明产品名称；安装软件不能直接证明服务运行；镜像名称不能直接证明所有运行组件；关联安全产品不能直接证明保护有效。来源只有部分信息时，返回对应部分。

### 6.5 上下文的时间、冲突与补充方式

告警本身的资源描述、当前资产观测和历史资产观测必须能够区分。新增资产数据通过独立记录与关系补充到查询视图，不修改原始告警载荷，也不把所有资产字段复制进每条告警修订。

资产组件分别保留来源与时效：实例信息可能较新，软件清单可能较旧，安全组查询也可能失败。返回整体上下文时，逐项表达状态，不能以一次查询成功代表全部信息完整。

多个来源值不一致时保留各自声明；展示层可使用明确、版本化的选择规则，但必须可查看其他来源和选择依据。

当前信息不能补写为告警发生时的历史状态。无历史观测时，明确返回“当前观测，历史未知”；观测时间也不能冒充来源未提供的有效起止时间。

一次未查询到资产不能直接记录为删除。已删除、已解绑等变化需要明确来源事件或具有可靠覆盖边界的对账过程支持。

### 6.6 查询体验

Web 告警详情和程序查询都应支持取得资产上下文，包括资产身份、基础信息、端口观测、安全组、软件与产品、标签，以及组件级来源与时效。

默认返回有界的上下文摘要，复杂规则和完整清单按需展开。外部来源可按请求选取，并受超时、数量和查询预算限制，避免查询单条告警时无界访问所有系统。

来源明确标注该资产“生产环境”“运行 Nginx”“安装某安全 Agent”时，使用者应能快速看到这些信息，同时能查到它们分别是谁、在什么时候报告的。

## 7. 事实关联规则

确定的资源关系必须基于来源原生引用、明确配置的身份映射，或完整作用域下的原生资源 ID 精确匹配。

检索命中与事实关系分开表达。同 IP、用户名、Hash 等条件可以返回匹配记录，但不证明资产或对象身份相同，也不得仅据此建立持久资产关系。

每项关系都需要说明：关联的记录或资源、关系类型、输入字段、来源依据、匹配规则版本，以及适用的时间或观测时间。企业手工维护的映射应标为配置声明。

同资源引用、同 IP、同用户名、同标签是不同关系。IP 等值查询可以返回相关记录，但不能自动合并资源身份；跨账号的同名资源、重用 IP 和缺少命名空间的用户名尤其需要保留歧义。

允许按已保存的主机→网卡→网络显式引用提供 VPC、子网、安全组和网卡的统计视角。多个关系下的告警分别计入各组，但每组内去重；总量单独按 Finding ID 统计。关系与摘要使用明确资产修订，区分当前观测与事件发生时配置。

归流不依据相似标题、时间接近或模型判断生成攻击链、攻击者身份、根因、攻击成功或横向移动结论。外部系统可以使用这些事实开展分析。

## 8. 目标能力与实现边界

本节定义最终能力范围，不构成当前开发阶段的全部交付要求。实现优先级和验收以第 12 节为准，以现有实现为基础渐进推进。

| 功能域 | 目标能力 |
| --- | --- |
| 接入管理 | 多来源、多账号及多作用域；只读鉴权、权限检查、限流、重试、断点、补采与来源能力说明 |
| 标准化与溯源 | 类型化事实契约、映射版本、未知字段保留、原始记录读取、确定性重映射 |
| 统一查询 | 身份、资源、账号、IP、用户、Hash、标签和时间筛选；稳定排序、分页、字段选择与精确版本读取 |
| 资产上下文 | 基础信息、网络与端口、安全组、软件与产品、标签；组件级来源、时效与缺口 |
| 跨源检索 | 围绕明确资源或可观测对象查询多种记录，返回匹配依据及各来源执行状态 |
| 组织与统计 | 客观分组、计数、趋势和成员展开；明确记录数、修订数及来源发生次数的不同含义 |
| 增量消费 | 对本地持久化事实提供稳定变化序号、精确修订和可重读游标，支持消费方幂等处理 |
| 覆盖与运行状态 | 支持哪些数据、范围与时间、水位、延迟、失败、权限和保留限制；区分空结果与未取得数据 |
| 消费入口 | Web、REST、只读 MCP 与只读查询 CLI 共用查询与授权语义；返回有界摘要及逐步展开的证据路径 |
| 运维与交付 | 简单自托管、版本化发布、备份恢复、升级规则、运行诊断及必要的访问审计 |

各来源应提供机器可读的能力说明，包括数据类型、可用筛选条件、时间依据、分页方式与限制。不支持的条件必须返回明确错误或限制，不得悄悄忽略后返回看似符合条件的结果。

查询保留三个层次：共同语义使用标准字段；明确索引或来源支持的专有字段使用带来源范围的查询；完整已保存载荷按需读取。不要求所有原生字段建立索引，也不要求所有来源支持相同操作。

修订、稳定变化序号和归流快照针对本地持久数据。远程查询保留来源的分页、一致性与时间语义，不支持的排序、精确版本、快照或增量功能必须明确返回限制，不伪造能力。

权限必须覆盖明细、上下文、关系、原始证据、分组统计与增量查询，不能通过关联结果暴露无权访问的数据。需要向不同程序开放不同账号时，必须先具备对应授权范围。多租户、SSO 和企业权限体系由实际部署需求推进，未实现前不宣称支持。

凭据加密存储、日志不输出凭据或完整敏感载荷、连接器最小只读权限，以及 REST / MCP / 查询 CLI 一致授权是基础交付要求；不以复杂 RBAC、SSO 或多租户的建设为前提。

本地资产标签、备注和告警标注属于使用者声明，与云原生字段及来源状态分开；不回写厂商，不制造来源告警变化。资产信息变化应进入相应资产记录的变化历史，不伪造告警内容变化。

## 9. 两种数据访问模式

| 模式 | 适用范围 | 可承诺的能力 |
| --- | --- | --- |
| 同步并保存 | Finding、资产观测、适合本地保留的低频事件 | 在已采集和声明保留范围内提供版本、原始证据、本地快照和持久变化流 |
| 远程按需查询 | 已在日志服务、SIEM 或云平台保存的大量事件 | 提供受限的统一查询适配，声明各来源权限、保留期、执行状态、分页、超时与成本限制 |

联邦查询先通过一个具体来源验证，再扩展通用能力。归流不承诺跨远程系统的全局事务快照、无限分页、精确总数或完整历史变化流，除非底层能力和实现能够证明。

默认查询优先使用已同步本地数据，不因读取告警详情自动刷新外部来源。实时访问必须显式请求，并配置超时、限流、缓存策略、记录与请求数量上限，必要时附带成本预算；同一资源的重复读取应复用缓存，超限或部分失败需可见。

远端证据需区分“可回查引用”与“已保存副本”。已保存副本保留实际取得的响应、查询范围、时间和校验信息；不能取得上游原始事件字节时，应说明这是 API 返回表示，不能宣称为原始事件的精确字节。

证据失效、数据到期和查询截断必须可见。保留策略按数据类型明确配置；“无损”适用于声明保留的数据范围，不等于无限期保存所有日志。

## 10. 架构约束

沿用现有逻辑分层，初期不要求拆为微服务：

1. **来源记录**：保存取得的载荷、接入范围、来源身份、采集时间和校验信息。
2. **标准事实**：Finding、资产观测、审计事件分别建模，共用来源、版本、时间和字段溯源机制。
3. **查询与关系索引**：支持类型化可观测对象、资源引用、时间查询和确定性关联；索引能够从保存的数据重建。
4. **查询视图**：明细、资产上下文、分组、变化、证据及覆盖信息，供 Web、REST、MCP 与查询 CLI 使用。

数据类型不能全塞入 Alert，也不强制所有记录满足同一组字段。标准事实是基础契约，OCSF 按实际类别和结构能力提供投影；不为凑齐标准而补造时间、身份或安全含义。

本地持久记录可以组成一致快照；混合远程结果时需要明确各部分的一致性。上下文组装、缓存或展示不能改变来源记录。

保持当前简单部署方向。数据库、搜索组件、队列及服务拆分由已测得的容量与运行要求驱动，不提前引入通用 DSL、规则引擎或图数据库。

## 11. 明确不做什么

| 范围外能力 | 处理方式 |
| --- | --- |
| 自行检测攻击、判定误报、风险评分、攻击归因和根因推断 | 提供事实和证据，交给使用者的规则、Agent 或人员 |
| 自动封禁、隔离、修改安全组、关闭漏洞、厂商状态写回 | 由企业响应系统执行，归流的数据访问接口保持只读 |
| 内置巡检 Agent、研判任务编排、通知、工单和拉群工作流 | 由消费端管理；归流自身采集所需的定时同步、重试与对账属于接入职责 |
| 自研主机采集 Agent、端口扫描器、漏洞扫描器和主动探测系统 | 接入已有系统报告的数据，明确来源 |
| 完整 CMDB、资产采购处置、业务生命周期管理与人工拓扑建设 | 仅维护调查需要的资产事实、原生资源关系与可追溯映射 |
| 默认集中采集并永久保存全部原始日志 | 按任务选择同步范围、保留策略或远程查询 |
| 把模糊相似、模型推断或同 IP 当作确定身份与攻击关系 | 返回明确匹配条件或候选关系，保留歧义 |
| 为替代既有平台而重复部署相同采集链路 | 根据实际缺口选择直接采集或复用现有来源 |

“只读”约束面向外部安全与资产系统；归流仍需管理自身配置、凭据、缓存、记录与使用者标注。

## 12. 推进顺序与验收

### 阶段 A：可靠的 Finding 数据访问

继续验证已有连接器的真实账号行为，完善对账、重试、字段准确性、历史修订、增量消费和覆盖表达；建立可直接使用的发布方式和接入指引。

验收：在明确账号、权限、API 与时间范围内与来源对账；重启、限流、迟到记录和失败重试后，数据及消费位置符合契约。真实账号验证与合成样本验证分别标记。

### 阶段 B：告警与资产上下文

先选一个云与云主机类型，建立独立资产数据类型，接入控制面基础信息、网络、安全组与标签。同一契约可以在没有真实账号时通过 SDK/接口契约与合成响应扩展到其他云，但每个真实来源必须单独验证，不能把合成验证当作已接入。完成“告警 → 云主机资产 → 同一明确资源身份的相关记录 → 原始证据”的 Web、REST、MCP 与查询 CLI 路径，公开每项信息的来源与时效。软件、进程、监听端口和 EDR 信息有来源需求再做。没有真实账号的功能使用合成数据验证并明确标记。

验收：同一条调查路径在 Web、REST、MCP 与查询 CLI 中取得一致结果；使用者能定位机器、读取基本背景、检索同一资源的其他记录，并展开配置和原始证据。缺失、过期、冲突和身份不确定时都有明确表达。没有软件或监听端口数据的来源不得显示为“未部署产品”或“没有开放端口”。完成后再接入外部 Agent 验证工具调用次数、无用数据量及是否仍需直接调用云 API。

### 阶段 C：一条跨类型调查路径

为同一资源接入一个适合的审计或既有 SIEM 来源。通过“告警 → 资产 → 相关事件 → 证据”验证跨类型查询；高数据量来源优先评估受限远程查询。

验收：与直接使用来源接口完成同一任务比较，记录接入成本、查询步骤、耗时、遗漏、人工介入及证据可重读性。归流的数据访问效果与外部 Agent 的研判质量分别评估。

### 阶段 D：按使用证据扩展

在真实团队重复使用后，选择第二种云、资源或查询来源验证契约复用。更多连接器、复杂权限、更大存储与企业交付能力由实际需求决定，不要求各云同时达到相同深度。

## 13. 当前基础与目标之间的关系

当前项目已具备 Finding 接入、原始载荷、字段溯源、修订历史、快照、Change Feed、覆盖信息，以及 Web / REST / MCP / 查询 CLI 入口，详见[现有数据契约](security-data-access.md)和[接入范围](../README.zh-CN.md#接入范围)。

阶段 B 首版已实现独立的云主机基础观测、完整作用域下的主机引用匹配及 Web / REST / MCP / 查询 CLI 调查路径。控制面适配已按同一契约覆盖六家云（腾讯云 CVM、阿里云 ECS、华为云 ECS、AWS EC2、GCP Compute、Azure VM），腾讯云已用一个真实账号的一台主机完成完整调查路径验证（schema 5 数据库、72 小时告警、告警→资产→网卡/网络引用→相关告警→原始证据，REST/MCP/查询 CLI 一致；Web 复用同一 REST）；其余五家仍只通过合成响应、SDK/接口契约与本地测试验证。腾讯云告警接入的真实账号验证不替代其他云的资产验证。按来源能力保留差异，例如 GCP 不把防火墙表达为实例安全组，华为云不补造子网，Azure 只跟随 VM 显式引用的网卡。主机及其显式网卡引用已在腾讯云、阿里云、AWS、Azure 落地为独立 `nic` 资产（含网卡→子网/安全组/主机关系）；GCP 的网卡不是独立资源，华为云 `ShowServer` 不返回 port ID，两者明确不建网卡资产。完整资产上下文、审计接入、通用远程查询和更细粒度授权仍属后续目标，详见现有数据契约中的资产首版范围。现有共享数据集与账号授权边界继续公开说明。

当前处于开发阶段，不为旧结构保留兼容分支。进入外部持续使用阶段前，需要明确版本、迁移、备份恢复和游标生命周期。

## 14. 后续功能的评审约束

每项新增能力都应能回答：

1. 服务哪个使用者，减少哪个具体的数据获取或调查步骤？
2. 数据来自哪里，来源身份、权限和覆盖范围是什么？
3. 字段、关系和派生结果能否解释、重放并返回证据？
4. 当前值、历史观测、未知、失败和过期如何区分？
5. 是否保持 Finding、资产和事件各自的语义，并明确来源声明与本地补充？
6. 是否引入了安全结论、响应动作或与当前任务无关的平台建设？
7. Web、API、MCP 和查询 CLI 的结果、授权与分页是否一致？
8. 能否用真实任务验证收益，并如实说明尚未支持的部分？

无法说明数据依据或任务收益的功能，应先补充验证；改变产品边界的功能，应先更新并审阅本约束。
