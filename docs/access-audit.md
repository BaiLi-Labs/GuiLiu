# 平台操作审计

归流记录 Web/REST 访问、查询 CLI、MCP HTTP 和 MCP stdio 调用。审计描述使用者如何访问平台，与厂商安全发现、Finding 修订和 Change Feed 分开保存，不产生安全判断。

## 记录范围

| 内容 | 记录方式 |
| --- | --- |
| 调用者 | 已认证用户 ID、用户名、角色、认证方式，以及 API Key 的独立 ID 和名称；不记录 Key 值、前缀或 Token Hash |
| 操作 | 请求开始/完成时间、入口、HTTP 方法与路径、路由模板、MCP 方法及工具名 |
| 查询 | 白名单内的账号、地域、资源、IP、等级、时间、分页、修订等条件；关键词及分组对象只保留 SHA-256 指纹和长度 |
| 实际范围 | Finding 查询记录服务端解析出的时间上下界、默认时间字段和固定快照序号 |
| 结果 | HTTP 状态、工具成功/失败、错误分类、耗时、写出的响应字节数，以及返回记录的 ID/修订/Hash、计数与分页位置 |
| 关联 | 服务端生成的 `request_id`，HTTP 经 `X-Request-ID` 返回；MCP HTTP 子调用引用对应 HTTP 审计序号 |
| 对端 | 直接连接的 IP；不信任客户端提交的 `X-Forwarded-For` 或 `X-Request-ID` |

每个 Agent 应使用单独命名的 API Key。共享同一把 Key 的多个 Agent 无法可靠区分；Key 身份证明的是凭据持有者，不证明背后使用了哪个模型。stdio 属于可信本地进程访问，标记为 `local_process`，不伪造远端用户或 Agent 身份。

入口 `surface` 取值为 `rest`、`cli`、`mcp_http`、`mcp_stdio`。查询 CLI 走 REST 时带 `X-Guiliu-Client: cli`，服务端据此记录 `surface=cli`；该请求头只是入口标记，不能替代认证或作为权限依据。普通 REST 程序不发送该头时仍记为 `rest`。

登录、鉴权失败、权限拒绝、账号/本地标注修改、API Key 创建与撤销、显式资产刷新和读取原始证据的请求也会记录。MCP 初始化、工具列表、通知、协议解析错误均有独立记录；工具失败不会因为 HTTP 返回 200 而被记为成功。账号同步的具体执行进度继续使用既有 Sync Run，不把“已接受同步请求”解释为同步已完成。查询 CLI 通过 HTTP 访问，正常进入本审计；`gl-cli accounts/user/sync/replay` 等直接访问本地数据库的受信管理命令仍不在本轮审计范围。

## 持久化与失败语义

执行前同步保存 `in_progress` 记录；HTTP 完成认证后，在进入业务处理器前持久化调用者身份。无法保存起始审计或身份时拒绝执行，REST 返回 `503 audit_unavailable`，MCP 返回协议错误。完成时再保存结果；即使客户端断开，也使用独立的短超时保存完成记录。

进程崩溃或完成记录写入失败可能留下 `in_progress`，它只证明请求开始，不证明操作完成或响应被客户端接收。写入失败会输出明确的运行日志。审计与业务操作并非同一个数据库事务，不宣称完成日志与业务写入具有原子提交语义。

查询参数与结果摘要分别限制为 16 KiB 和 64 KiB；返回引用最多列出 200 条。超限明确标记截断或省略，并保留摘要指纹，不声称记录了全部正文。API Key、Cookie、Authorization、密码、云凭据、任意请求正文和原始证据正文不会被复制进审计；已知凭据格式也会在允许的文本字段中脱敏。

## 管理员查询

Web 的“操作审计”页仅管理员可用，支持筛选、分页、展开详情与“查看同一请求”。相同权限约束适用于 REST：

```http
GET /api/v1/audit-events?api_key_id=<key-id>&surface=mcp_http&limit=20
GET /api/v1/audit-events?request_id=<request-id>
```

支持 `request_id/user_id/username/api_key_id/surface/operation/tool/outcome/start/end/before_sequence/limit`。`start/end` 使用 RFC3339，`limit` 为 1–100。按单调审计序号倒序返回，`next_cursor` 用作下一页的 `before_sequence`；新请求不会挤乱已向后翻阅的范围。首版不提供审计修改或删除接口。

审计摘要是调查索引。按保存的 Finding ID、修订和快照查询原始数据，才能核对来源证据。资产当前观测没有固定列表快照，不能据此宣称可以重放历史资产列表。

## 保存与边界

生产环境保存在同一个 SQLite 数据库内；Mock 使用内存数据库，退出后不保留。`audit.retention_days` 默认 90，可设为 1–3650；启动时及 HTTP 服务每小时执行有数量上限的过期清理，积压可能分批清除。stdio 长驻进程在启动时执行清理。审计序号独立于 Finding 变化序号，记录保留不随用户会话、API Key 撤销而删除。

运行日志同时输出审计序号、请求 ID、调用者 ID、工具、结果和耗时，便于对照；数据库审计记录不受运行日志级别影响。备份与恢复数据库会同时保存/恢复审计，恢复旧备份并不证明恢复之后的操作从未发生。

当前属于本机持久审计，没有外部不可变存储、签名链或防篡改承诺。数据库文件的管理者仍能修改它；需要此类保证时，再将审计发送至使用者自己的受控日志系统。审计含账号、资源与查询元数据，访问和备份权限应与安全数据一致。
